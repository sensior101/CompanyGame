# 상가 블록 로우폴리 재제작

기존 CB_01~CB_08 설계를 참고해 CompanyGame의 무광 단색 외관 스타일에 맞춘 Blender 모델 8종입니다. 기존 모델의 12×8m 본체, 3층(4m/3.2m/3.2m), 테라스와 옥상 특징을 유지했습니다.

- `Overview.png`: 전체 8종 Blender 렌더
- `Review/index.html`: 기존/새 모델 비교 및 개별 파일 링크
- `Models/`: 편집 가능한 Blender 원본 8개
- `Exports/`: FBX 8개 및 GLB 8개
- `Previews/`: 개별 렌더 8개
- `Catalog/catalog.json`, `manifest.json`: 치수, 재질, 삼각형 수, 파일 경로

## 외형 변경

실사 석재·벽돌 텍스처를 무광 색상 면으로 바꾸고 창틀과 난간을 두껍게 정리했습니다. 창 분할과 옥상 설비의 작은 부품을 줄이고, 식재는 면이 드러나는 형태로 제작했습니다. 4번 코너는 8개 평면으로 구성합니다. 창은 불투명 색상 재질입니다.

## 변경 파일·재사용·영향

1. **기존 수정 파일:** 없음. 기존 상가 폴더의 작업 전 168개 파일 SHA-256이 유지됐습니다. 새 파일은 `LowPoly_20261104` 안에만 생성했습니다.
2. **신규 파일 이유:** `build_lowpoly.py`는 원본을 보존하면서 로우폴리 형상·재질을 생성하는 변형 제작기입니다. `build_overview.py`는 8종 비교 렌더를 모읍니다. `Review/verify_pack.py`는 내보내기 왕복 검증, `Review/build_review.py`는 로컬 전후 비교 페이지 생성용입니다. 모델/출력/렌더/메타데이터는 이 제작 결과입니다.
3. **재사용:** 기존 `Designs/common.py`의 `Building`을 상속하고 8개 개별 설계를 읽습니다. 벽 개구부, 평면, 계층, UV, 문 및 간판 앵커를 재사용하고 창·난간·식재·재질 생성만 단순화했습니다. 검증은 기존 `Tools/validate_exports.py`의 `finite`, `descendant`, `check_uv`, 앵커 목록을 재사용합니다.
4. **데이터 흐름:** 기존 개별 설계 → 로우폴리 생성기 → 독립 BLEND/FBX/GLB → 카탈로그/렌더 → 파일 재불러오기 검증. 게임 런타임 데이터 흐름은 변경하지 않았습니다.
5. **중복 구현:** 신규 게임 관리자·인벤토리·저장·거래 기능은 없습니다. 모델 생성은 기존 건축 유틸리티를 확장했습니다.
6. **기존 기능 영향:** 기존 원본과 Unity 씬/프리팹/공개 API에 변경이 없습니다. `EntryAnchor`, `InteriorSpawnAnchor`, `Door_Leaf_01/02`, 간판 4개 앵커를 보존했습니다. 간판 이미지는 미지정 상태입니다.
7. **검증:** 아래 결과와 `Review/Validation.json` 참조. Unity 임포트/게임 내 외관/충돌/NavMesh/출입/문 동작/실내는 이번에 실행하거나 구현하지 않았습니다. 원본 모델과 새 렌더는 조명 조건이 다릅니다.

## 확인 결과

- Blender 원본/FBX/GLB 총 24개, 검사 722개 통과.
- 유한 좌표·변환, 메타데이터와 실제 크기/삼각형 수 일치, UV/재질, 평면 셰이딩 노멀, 문 자식 메시, 간판 보드/UV/앵커 보존 확인.
- FBX/GLB 임포터의 smooth 플래그 대신 실제 split corner normal과 면 노멀을 비교해 평면 셰이딩을 검증했습니다.
