# 달동네 프로젝트 게임 기획안 초안

**작업명:** 달동네, 오늘도 영업 중  
**장르 제안:** 3D 마을 탐험 + 작은 가게 운영 시뮬레이션  
**시점/분위기:** 로우폴리 사선 시점, 서울 외곽의 따뜻하고 조금 낡은 동네  
**기준 에셋:** Unity `Assets/Scenes/DaldongneWarmMap.unity` 및 `Assets/Art/Daldongne/Players/`  
**문서 상태:** 기획 초안. 장르와 스토리는 결정안이 아니라 현재 에셋에 맞춘 제안이다.

## 1. 한 문장 기획

플레이어가 경사진 달동네를 걸으며 주민의 부탁을 해결하고 작은 가게를 가꾸어, 쇠퇴한 골목에 손님과 생활의 온기를 되돌리는 게임.

건물을 크게 확장하는 도시 건설 게임보다 **동네를 직접 걸어 다니며 발견하고 돌보는 경험**에 무게를 둔다. 맵의 계단과 높낮이, 서로 다른 상점, 지하철역과 버스 정류장을 게임 진행의 뼈대로 활용한다.

## 2. 플레이어 경험

첫 10분에 플레이어는 역 앞에서 시작해 골목을 탐색하고, 베이커리의 첫 부탁을 받는다. 시청에서 필요한 안내를 확인하고 동네 가게를 도와 재료를 전달한다. 가게의 진열대에 변화가 생기고, 주민 한 명이 새 대사를 건넨다. 이 작은 변화를 통해 ‘내 행동이 동네에 남는다’는 보상을 느끼게 한다.

한 번의 짧은 플레이 흐름은 **동네 걷기 → 주민/가게 발견 → 부탁 선택 → 이동·배달·정리 → 가게/골목 변화 확인**이다. 반복 플레이에서는 새로운 주민, 의뢰, 가게 장식, 시간대별 풍경을 추가한다.

## 3. 공간과 콘텐츠 역할

| 현재 에셋 | 게임 안에서의 역할 제안 | 첫 구현 범위 |
|---|---|---|
| 지하철역 | 시작점, 새로운 손님이나 방문자 유입 | 시작 위치·안내 표지 |
| 버스 정류장 | 동네 소식과 배달 목적지 | 상호작용 지점 1개 |
| 시청 | 마을 게시판, 주민 부탁 접수 | 의뢰 게시판 1개 |
| 베이커리 | 첫 번째 가게, 재료 조달·진열 | 첫 의뢰와 시각적 변화 |
| 카페 | 주민 만남, 대화와 두 번째 의뢰 | NPC 1명과 대화 |
| 빨래방·편의점·분식집·햄버거집 등 | 후속 의뢰와 동네 생활감 | 입구/표지 구분, 기능은 후속 단계 |
| 계단·연결 골목 | 탐색 동선, 지름길 발견 | 기존 충돌·보행 경로 활용 |

건물 내부와 차량 운전은 이 초안의 첫 플레이 범위에 넣지 않는다. 외부에서의 탐색과 상호작용이 충분히 재미있는지 먼저 확인한다.

## 4. 핵심 시스템 제안

### 탐색과 조작

현재 Unity 씬에는 여자·남자 로우폴리 플레이어가 있고, `1`/`2`로 외형을 바꿀 수 있다. `WASD` 이동, `Shift` 달리기, `F` 걷기/전체 맵 시점 전환, `R` 역 앞 복귀가 동작한다. 사선 카메라로 동네 전체를 보고, 걷기 시점으로 골목의 세부 요소를 살핀다.

기획 단계에서는 두 외형을 **게임 규칙상 동등한 선택지**로 둔다. 의상·색상 변경은 후속 확장이다.

### 주민과 부탁

첫 구현은 주민 두 명, 의뢰 세 개로 제한한다. 의뢰는 게임 화면에서 목표·목적지·완료 조건을 명확히 보여준다. 예시:

1. 베이커리 주인이 필요한 물품을 부탁한다.
2. 플레이어가 시청 게시판에서 위치 힌트를 얻는다.
3. 버스 정류장 인근에서 물품을 찾아 베이커리에 전달한다.
4. 베이커리 진열대가 바뀌고 주민 대사가 갱신된다.

배달만 반복하지 않도록 후속 의뢰는 사진 찍기, 간판 수리 준비, 주민에게 물건 전달하기처럼 동네 공간을 다른 방식으로 쓰게 한다.

### 가게 성장

첫 번째 가게는 베이커리 하나로 시작한다. 플레이어가 의뢰를 완료하면 진열·화분·조명처럼 **눈에 보이는 변화**가 한 단계씩 생긴다. 수익 숫자와 복잡한 경영 지표는 재미 검증 뒤에 도입한다.

### 시간과 분위기

현재 맵의 벽돌, 바랜 회벽, 식물, 전봇대, 따뜻한 실내 조명은 핵심 미술 방향이다. 추후 낮·해질녘·밤의 조명 차이와 주민 동선으로 작은 동네의 일상을 만든다. 시간 시스템은 현 단계에서 구현 완료로 보지 않는다.

## 5. 아트·사운드 방향

- **건물:** 붉은 벽돌, 덧칠한 회벽, 조금 낡은 목재 차양, 작은 간판. 허름함은 파손보다 사용감으로 표현한다.
- **색:** 벽돌 주황·따뜻한 크림색을 중심에 두고, 청록과 짙은 파랑을 가게·교통시설의 구분 색으로 쓴다.
- **소품:** 화분, 빨랫줄, 배수관, 실외기, 자전거, 자판기, 전봇대. 보행로를 막지 않는 위치에 배치한다.
- **인물:** 현재 플레이어의 각진 저폴리 형태와 단순한 얼굴 비율을 NPC에도 적용한다.
- **사운드 제안:** 낮에는 생활 소음과 버스 소리, 저녁에는 멀어진 교통 소리와 가게 실내음을 얇게 겹친다. 사운드 에셋은 아직 확인되지 않았다.

## 6. 현재 Unity 에셋 기준 구현 상태

| 항목 | 확인한 상태 | 기획 시 해석 |
|---|---|---|
| `DaldongneWarmMap.unity` | 열 수 있는 3D 마을 씬 | 첫 플레이 장소 |
| `WarmVillage/DaldongneWarmTown.prefab` | 건물·도로·계단 등 맵 모델 | 탐색 공간의 기반 |
| `Players/PlayerFemale.prefab`, `PlayerMale.prefab` | 외형·이동·충돌 구성 | 플레이어 외형 선택 기반 |
| `DaldongneVillageWalker.cs` | 걷기·달리기·카메라 전환·복귀 | 탐색 프로토타입 |
| `DaldongnePlayerAppearance.cs`, `DaldongneAvatarMotion.cs` | 외형 전환·부품 관절 동작 | 캐릭터 표현 기반 |
| `QuestManager`, `NPCManager`, `CompanyManager` 등 | 파일은 있으나 현재 동작 로직은 거의 없음 | 개발 예정 항목으로만 표기 |
| `SaveManager`, `UIManager`, `TimeManager` 등 | 빈 틀에 가까움 | 저장·화면·시간 기능은 별도 구현 필요 |

맵 기준 계단 13개와 연결 보행로 24개, 총 37개 동선이 있다. 기존 검증 자료는 플레이어 크기 기준 바닥·통로 2,499지점과 실제 `CharacterController` 양방향 이동 74회를 통과했다. 여자·남자 외형을 적용한 플레이어로는 148회 이동 검사가 통과했다. 이 수치는 **현재 맵과 해당 크기의 플레이어**에 관한 결과이며, NPC 길찾기까지 검증한 것은 아니다.

## 7. 첫 플레이 가능 버전(MVP)

**목표:** 처음 실행한 사람이 설명 없이 10~15분 안에 ‘골목을 걸어 부탁을 해결하고 동네가 변한다’를 경험한다.

1. 시작 안내와 조작 도움말을 화면에 표시한다.
2. 베이커리 주인·카페 손님 등 주민 2명을 배치하고 간단한 대화를 제공한다.
3. 시청 게시판, 베이커리, 버스 정류장에 상호작용 지점을 만든다.
4. 의뢰 3개를 시작·진행·완료 상태로 관리한다.
5. 첫 의뢰 완료 시 베이커리 진열 또는 골목 조명이 바뀐다.
6. 진행 상태를 저장·불러오기 가능하게 한다.
7. 목적지 표식과 대화 글씨를 게임 화면에서 읽을 수 있게 한다.

**완료 기준:** 새 게임 시작부터 첫 의뢰 완료까지 끊김 없이 진행되고, 게임을 껐다 켜도 완료 상태와 가게 변화가 유지된다. 계단과 입구에서 플레이어가 끼지 않는다.

## 8. 개발 순서와 결정할 문제

| 순서 | 작업 | 확인 방법 |
|---|---|---|
| 1 | 게임 시작 화면·조작 안내·상호작용 버튼 | 처음 보는 사람이 도움 없이 첫 대화 시작 |
| 2 | 주민·대화·의뢰 1개를 끝까지 연결 | 베이커리 의뢰 완료 가능 |
| 3 | 의뢰 3개와 가게 변화 | 위치 이동과 보상이 반복적으로 이해됨 |
| 4 | 저장, 목적지 UI, 소리 | 재시작 후 상태 일치, 작은 화면에서도 읽힘 |
| 5 | 후속 가게·주민·시간대 확장 | 기본 루프가 재미있다는 플레이테스트 결과 확보 |

기획 확정 전에는 **주인공이 가게 주인인지, 동네 주민인지**, **가게 운영의 비중**, **목표 플랫폼(PC/모바일)**을 결정해야 한다. 이 초안은 PC 키보드 조작을 기준으로 작성했다. 모바일로 확장한다면 가상 조이스틱, 카메라 조작, UI 크기, 맵 성능을 별도로 설계해야 한다.
